# Do 面板 — 纯文本 todo 持久化格式设计

> 状态：v2（2026-07-15）· 面向 `Do` 面板的本地持久化格式与语义定义
> 代码落点：`Core/Do/`（模型 + Store）、`DoViewModel.swift`、`DoView.swift`
> 云同步（本地文件如何镜像到 Google Drive）见 [google-drive.md](google-drive.md)
>
> **升级版**：`Goal` 面板是 Todo 的升级版（同一套两级结构，条目 = 目标文档），UI 对齐契约与存储格式见 [goal.md](goal.md)。改 Do 面板外壳时需同步看 goal.md 的对齐要求。

## 1. 目标与取舍

- **人类可读、可手改**：文件本身就是能用任何编辑器/预览器看的 Markdown，不用 App 也能读。
- **活动 / 归档分离**：活动清单只放**未完成**项；一个待办**完成即移出活动**、写入其**完成月份**的归档文件（记录起止时间）。活动清单保持「要做的事」，历史沉淀到归档。
- **结构分层**：固定「领域」(tab) = 一个活动文件；可增删「主题」= 二级标题；条目 = 列表项。
- **本地 = Drive 镜像源**：文件名/内容与 Drive 一致，Drive 只是把本地文件原样上传（见 google-drive.md）。

## 2. 存储位置与文件

```
~/Documents/houmao/do/
  工作.txt                 # 活动：工作 tab（仅未完成项）
  生活.txt                 # 活动：生活 tab
  工作·2026-07·归档.txt    # 归档：工作 tab、2026 年 7 月完成的项
  生活·2026-07·归档.txt
```

- 领域 tab 固定（工作/生活）；文件名用**中文显示名 + `.txt`**（与 Drive 1:1 镜像；扩展名 `.txt`、内容仍是 Markdown）。
- 归档文件按 **tab × 月份**滚动，一个 `<tab>·<yyyy-MM>·归档.txt`。
- 目录不存在时首次保存自动创建。
- **旧版迁移**：若新的 `工作.txt` 不存在但旧版 `work.md`/`life.md` 存在，首次加载导入其中**未完成**项作为活动（已完成项无时间戳，丢弃）。

## 3. 文件格式

### 3.1 活动文件（`工作.txt`）

```markdown
# 工作

## todo
- [ ] 写周报 <!--2026-07-02-->
  周报要点：
  - 本周进度
  - 下周计划
- [ ] 修复登录 bug <!--2026-07-03-->

## 学到老
- [ ] 阅读 Swift 并发进阶 <!--2026-07-01-->
```

| 元素 | 语法 | 含义 |
| --- | --- | --- |
| 领域标题 | `# <显示名>` | tab 名（工作/生活），仅展示 |
| 主题 | `## <主题名>` | 可增删清单；出现顺序 = 展示顺序 |
| 未完成条目 | `- [ ] <文本> <!--yyyy-MM-dd-->` | 尾部注释记录**创建日期**（缺失则视为「今天」） |
| 条目正文 | 条目行下方**缩进两格**的续行 | 可选 Markdown 详情；列表里默认只显示标题，双击整行进入全文编辑 |
| 空主题 | 只有 `## <主题名>` | 合法，展示为空清单 |

活动文件**只含未完成项**（无 `- [x]`）。

### 3.2 归档文件（`工作·2026-07·归档.txt`）

```markdown
# 工作 · 归档 2026-07

## todo
- 写周报 · 起 2026-07-02 · 止 2026-07-05
```

| 元素 | 语法 | 含义 |
| --- | --- | --- |
| 归档标题 | `# <显示名> · 归档 <yyyy-MM>` | 展示 |
| 主题 | `## <主题名>` | 归档条目按原主题分组；空主题不写出 |
| 归档条目 | `- <文本> · 起 <yyyy-MM-dd> · 止 <yyyy-MM-dd>` | 起=创建日、止=完成日 |

## 4. 解析 / 序列化约定

- 活动：`##` 开主题；`- [ ] 文本 <!--日期-->` 为条目（日期从注释取，缺失=当前时间）；条目行下方**缩进两格**的续行拼成该条目的正文（去掉一层两格缩进），直到下一条目/主题；其余行忽略。
- 归档：`##` 开主题；`- 文本 · 起 D · 止 D` 为条目；其余忽略。
- 序列化为规范格式（App 保存时整文件重写）。⚠️ 手改的自由文字/非清单内容会在下次保存被规范化丢弃。
- 换行按 `isNewline` 切分，兼容手改的 CRLF。

## 5. 运行时模型（不落盘的部分）

- `DoItem { id: UUID, text, body, createdAt, completedAt? }`：`done = completedAt != nil`；`text`=标题（列表行）、`body`=可选 Markdown 正文（双击全文编辑）。`id` 仅 SwiftUI 会话内识别，不落盘。
- `DoTopic { id, title, items }`（活动 items 均未完成）。
- 领域枚举 `DoTabKind { work, life }`：`title`(工作/生活)、`activeFileName`(工作.txt)、`archiveFileName(month:)`、`legacyFileName`(work.md)、`defaultTopics`。
- 活动文件缺失且无旧版可迁移时，用 `defaultTopics` 播种：工作=`todo`/`学到老`，生活=`衣食住行`/`吃喝玩乐`。

## 6. 交互语义

- **交互只有两个编辑入口**（无独立「添加待办」输入框；均唤起 houmao 通用 Markdown 编辑器窗口）：
  - **新增**：列表底部 `+` 按钮 → 打开编辑器（空白）；保存时首行非空则在当前主题末尾新建条目，`createdAt` = 保存时的现在。
  - **编辑（已有行双击）**：打开编辑器，预填「首行=标题、其余=正文」；保存提交（首行=标题/其余=正文），**标题清空则删除该条目**（待办以首行标题为身份，无标题即无效）。
  - 编辑器窗口为**全局唯一、通用**（`MarkdownEditorView` + `AppDelegate.presentMarkdownEditor`），保存图标或关闭窗口（红点/⌘W）都=保存（无独立丢弃路径）。
- **完成（勾选圆圈）**：`completedAt` = 现在 → **从活动移出** → 追加到**完成月份**的归档文件（按原主题分组）→ 活动与归档两文件各自持久化，并各自镜像到 Drive。UI 中该条随即消失（活动只显示未完成）。⚠️ 当前归档格式为单行，**完成时条目 `body` 不入档（丢弃）**，见 §7。
- **删除**：从活动移除（不进归档）。
- **主题增/改名/删/拖排**：改写活动文件的 `##` 段；删除含条目主题需二次确认。归档文件为历史快照，不随主题改名回改。
- 任一变更后立即持久化对应文件（整文件重写，`.atomic`）+ 防抖镜像 Drive。

## 7. 未来扩展位（暂不做）

- **归档保留正文**：当前归档单行格式不含 `body`，完成带正文的条目会丢正文；如需保留要扩归档格式（如正文另起缩进续行）。
- 归档浏览 UI（当前归档仅文件，DoView 不展示）。
- 条目优先级 / 到期日（可在活动行尾追加 `@due(...)` 之类，解析器保留未识别 token）。
- 与 `/save` notes 打通。
