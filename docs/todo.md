# Do 面板 — 纯文本 todo 持久化格式设计

> 状态：v1（2026-07-15）· 面向 `Do` 面板的本地持久化格式与语义定义
> 代码落点：`Core/Do/`（模型 + Store）、`DoViewModel.swift`、`DoView.swift`

## 1. 目标与取舍

- **人类可读、可手改**：文件本身就是一份能用任何编辑器/预览器看的 Markdown 任务清单，不用 App 也能读写。
- **todo 语义优先**：每条是「未完成 / 已完成」两态，采用 Markdown 事实标准的任务列表 `- [ ]` / `- [x]`（GitHub、Obsidian、Bear 通用）。
- **结构与内容分层**：固定「领域」= 文件；可增删「主题」= 二级标题；条目 = 任务列表项。
- **简单优先**：不引入数据库、不存 id/时间戳等元数据（v1）。文件即真相（App-managed canonical file）。

## 2. 存储位置

```
~/Documents/houmao/do/
  work.md     # 领域「工作」
  life.md     # 领域「生活」
```

- 两个「领域」tab 是**固定**的，用**固定英文文件名**（`work` / `life`）作稳定身份，避免中文文件名的编码/大小写问题；显示名（工作/生活）写在文件 H1。
- 目录不存在时首次保存自动创建（`FileManager.createDirectory`）。

## 3. 文件格式（每个领域一份）

```markdown
# 工作

## todo
- [ ] 写周报
- [x] 修复登录 bug

## 学到老
- [ ] 阅读 Swift 并发进阶
```

语法规则：

| 元素 | 语法 | 含义 |
| --- | --- | --- |
| 领域标题 | `# <显示名>` | 该文件对应的 tab 名（工作/生活）。仅用于展示，身份由文件名决定 |
| 主题 | `## <主题名>` | 一个可增删的清单；**出现顺序 = 展示顺序** |
| 未完成条目 | `- [ ] <文本>` | 归属于其上方最近的主题 |
| 已完成条目 | `- [x] <文本>` | 同上；`x` 大小写均可解析 |
| 空主题 | 只有 `## <主题名>`、下方无条目 | 合法，展示为空清单 |

## 4. 解析（parse）与序列化（serialize）约定

**解析**（宽松，容错手改）：

1. 按行扫描。遇到 `##` 开一个新主题（主题名 = 去掉前缀并 trim）。
2. 遇到 `- [ ]` / `- [x]`（`-`与`[`之间、`]`之后允许可选空格）→ 归入「当前主题」；无当前主题则忽略。
3. 其余行（含 `#` H1、空行、自由文字）**忽略**。
4. 主题名重复时按先后各自独立保留（不合并），保持所见即所得。

**序列化**（规范化，App 保存时统一重写）：

```
# <显示名>
<空行>
## <主题1>
- [ ] / - [x] 逐条
<空行>
## <主题2>
...
```

- 每个主题块之间空一行；空主题只写标题行。
- 条目顺序 = App 内当前顺序（不自动把已完成沉底，保持用户/文件顺序）。

> ⚠️ **规范化副作用**：文件是 App 托管的规范格式。手动加入的自由段落文字、非任务列表内容，在 App 下一次保存时会被丢弃。若要长文笔记请用 `/save` notes，不要写进 `do/*.md`。

## 5. 运行时模型（不落盘的部分）

- `DoItem { id: UUID, text, done }`、`DoTopic { id: UUID, title, items }`：`id` 仅用于 SwiftUI 会话内识别，**不写入文件**；重新加载会重新分配。因为格式里不做跨会话引用，所以无需持久 id。
- 领域用枚举 `DoTabKind { work, life }` 固定；`defaultTopics`：
  - `work` → `todo`、`学到老`
  - `life` → `衣食住行`、`吃喝玩乐`
- 文件缺失或无主题时，用 `defaultTopics` 播种（空清单）。

## 6. 交互语义（与格式的对应）

- 勾选/取消 = 翻转 `- [ ]` ⇄ `- [x]`，位置不动。
- 新增条目 = 追加到当前主题末尾（`- [ ] 文本`）。
- 删除条目 = 从该主题移除对应行。
- 主题增 / 改名 / 删 / 拖动排序 = 增删/改写/重排 `##` 段（排序即文件内 H2 顺序）；删除含条目的主题需二次确认。
- 任一变更后**立即持久化**对应领域文件（整文件重写，`.atomic`）。

## 7. 未来扩展位（v1 不做）

- 条目元数据（创建/完成时间、优先级、到期日）：可在行尾用 `<!-- meta -->` 或 `@due(2026-07-20)` 内联，解析器保留未识别 token。
- 与 `/save` notes、云同步（Drive 目录映射）打通。
